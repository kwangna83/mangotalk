## ADDED Requirements

### Requirement: 이미지 크기 메타데이터
시스템은 새 채팅 이미지의 디코드된 픽셀 너비와 높이를 첨부 메타데이터에 MUST 저장하고 메시지 조회 결과에 포함해야 한다.

#### Scenario: 새 이미지 업로드
- **WHEN** 사용자가 지원되는 이미지를 채팅방에 업로드한다
- **THEN** 시스템은 이미지의 양수 너비와 높이를 첨부 레코드에 저장하고 메시지와 함께 반환한다

#### Scenario: 크기 정보가 없는 기존 이미지
- **WHEN** 사용자가 너비 또는 높이가 저장되지 않은 기존 이미지 메시지를 조회한다
- **THEN** 시스템은 메시지 조회를 실패시키지 않고 크기 정보가 없는 호환 데이터로 반환한다

### Requirement: 안정적인 이미지 레이아웃
시스템은 이미지 다운로드 전후에 메시지 목록의 이미지 표시 영역이 불필요하게 변하지 않도록 알려진 종횡비를 MUST 적용해야 한다.

#### Scenario: 크기 정보가 있는 이미지 로딩
- **WHEN** 이미지 메시지에 저장된 너비와 높이가 있다
- **THEN** 시스템은 다운로드 전에 해당 종횡비로 영역을 예약하고 로딩 완료 후에도 같은 영역을 유지한다

#### Scenario: 기존 이미지 크기 측정
- **WHEN** 크기 정보가 없는 기존 이미지가 성공적으로 디코드된다
- **THEN** 시스템은 측정한 크기를 현재 설치의 로컬 인덱스에 저장하여 다음 접속의 placeholder 비율에 재사용한다

### Requirement: 재접속 간 이미지 캐시
지원되는 Web 환경에서 시스템은 signed URL과 무관한 안정적 첨부 키로 성공적으로 다운로드한 이미지 바이트를 MUST 영속 캐시해야 한다.

#### Scenario: 캐시된 이미지로 다시 접속
- **WHEN** 현재 사용자가 이전에 다운로드한 동일 첨부가 유효한 로컬 캐시에 있는 상태로 채팅방에 다시 접속한다
- **THEN** 시스템은 signed URL 발급과 새 이미지 바이트 다운로드 없이 로컬 캐시에서 이미지를 표시한다

#### Scenario: signed URL 변경
- **WHEN** 동일 첨부에 새 토큰 또는 만료 시각이 포함된 다른 signed URL이 발급된다
- **THEN** 시스템은 URL 문자열이 아니라 첨부 ID 또는 Storage 경로를 기준으로 기존 캐시를 재사용한다

#### Scenario: 캐시 미지원 플랫폼
- **WHEN** 실행 플랫폼이 영속 이미지 캐시를 지원하지 않거나 캐시 초기화가 실패한다
- **THEN** 시스템은 오류로 채팅을 차단하지 않고 signed URL 네트워크 표시 방식으로 동작한다

### Requirement: 캐시 실패 복구
시스템은 누락·손상·퇴거된 캐시를 감지하고 참여 권한을 반영한 최신 signed URL로 이미지를 MUST 복구해야 한다.

#### Scenario: 캐시 누락 또는 브라우저 퇴거
- **WHEN** 캐시 인덱스에 기록된 이미지 바이트가 실제 저장소에 없다
- **THEN** 시스템은 현재 signed URL로 이미지를 다시 다운로드하고 성공한 결과를 캐시에 복원한다

#### Scenario: 손상된 캐시 항목
- **WHEN** 캐시된 이미지가 비어 있거나 지원 MIME 또는 이미지 디코드 검증에 실패한다
- **THEN** 시스템은 해당 항목을 삭제하고 네트워크에서 한 번 다시 받아 표시를 시도한다

#### Scenario: 동일 이미지 동시 요청
- **WHEN** 목록과 상세보기 또는 여러 위젯이 동일 첨부 이미지를 동시에 요청한다
- **THEN** 시스템은 진행 중인 다운로드를 공유하여 동일 이미지의 중복 네트워크 요청을 만들지 않는다

### Requirement: 제한된 캐시 보존
시스템은 영속 이미지 캐시의 항목 수와 총 byte 크기를 MUST 제한하고 오래 사용하지 않은 항목부터 정리해야 한다.

#### Scenario: 캐시 한도 초과
- **WHEN** 새 이미지 저장으로 설정된 항목 수 또는 총 용량 한도를 초과한다
- **THEN** 시스템은 최근 접근 시각이 가장 오래된 항목부터 삭제하여 한도 안으로 복귀한다

#### Scenario: 브라우저 저장 공간 부족
- **WHEN** 브라우저가 quota 부족으로 캐시 저장을 거부한다
- **THEN** 시스템은 오래된 항목을 정리하고 한 번 재시도하며 실패해도 네트워크 이미지는 계속 표시한다

#### Scenario: 캐시 인덱스 접근 갱신
- **WHEN** 스크롤이나 위젯 재빌드로 캐시된 이미지를 짧은 시간에 반복 조회한다
- **THEN** 시스템은 접근 시각 변경을 일괄 저장하여 각 렌더링마다 영속 저장소 쓰기를 발생시키지 않는다

### Requirement: 제한된 이미지 작업 동시성
시스템은 긴 이미지 대화를 표시할 때 네트워크와 디코딩 메모리가 급증하지 않도록 서로 다른 이미지 작업의 동시성을 MUST 제한해야 한다.

#### Scenario: 여러 이미지 동시 표시
- **WHEN** 화면과 사전 로딩 범위에서 네 개를 초과하는 이미지가 동시에 캐시 miss 상태가 된다
- **THEN** 시스템은 최대 네 개의 다운로드·검증 작업만 실행하고 나머지는 순서대로 대기시킨다

#### Scenario: 채팅 목록 이미지 디코딩
- **WHEN** 고해상도 이미지를 제한된 크기의 채팅 버블에 표시한다
- **THEN** 시스템은 버블 표시 크기에 맞는 축소 디코딩을 사용하고 원본 해상도 디코딩을 상세보기 전까지 피한다

### Requirement: 사용자별 private 캐시 격리
시스템은 private 채팅 이미지 캐시를 현재 인증 사용자에게만 연결하고 로그아웃 시 해당 사용자의 캐시를 MUST 제거해야 한다.

#### Scenario: 다른 사용자로 전환
- **WHEN** 동일 브라우저에서 캐시를 생성한 사용자와 다른 사용자가 로그인한다
- **THEN** 시스템은 이전 사용자 소유 캐시 항목을 새 사용자에게 반환하지 않는다

#### Scenario: 로그아웃
- **WHEN** 사용자가 현재 설치에서 로그아웃한다
- **THEN** 시스템은 해당 사용자가 소유한 채팅 이미지 캐시와 인덱스를 삭제하며 정리 실패가 로그아웃을 차단하지 않는다
