## Why

MangoTalk은 채팅방에 다시 접속할 때마다 이미지마다 새 signed URL을 발급해 브라우저 캐시를 안정적으로 재사용하지 못하고, 이미지 로딩 전후의 높이가 달라져 메시지와 스크롤 위치가 이동한다. 비공개 이미지 접근 제어를 유지하면서 반복 다운로드와 레이아웃 이동을 줄여 재접속 경험을 안정화해야 한다.

## What Changes

- 이미지 업로드 시 원본의 너비와 높이를 첨부 메타데이터에 저장하고 메시지 조회 결과에 포함한다.
- 이미지 다운로드 전에 저장된 종횡비로 표시 영역을 예약하여 로딩 완료 후 메시지 높이가 변하지 않게 한다.
- 첨부 ID 또는 Storage 경로처럼 signed URL과 무관한 안정적 키를 사용해 이미지 바이트를 브라우저에 영속 캐시한다.
- 영속 캐시를 우선 사용하고, 캐시 누락·손상·퇴거 시에만 참여 권한을 확인하여 새 signed URL로 이미지를 내려받는다.
- 캐시 용량과 보존 기간을 제한하고 로그아웃 시 비공개 이미지 캐시를 삭제한다.
- 크기 메타데이터가 없는 기존 이미지에는 호환 가능한 placeholder를 사용하고, 로드 후 측정값을 현재 설치의 캐시에 보관한다.

## Capabilities

### New Capabilities

- `stable-chat-images`: 채팅 이미지의 크기 메타데이터, 레이아웃 안정성, 재접속 간 영속 캐시, 실패 복구 및 개인정보 정리 동작을 정의한다.

### Modified Capabilities

- 없음.

## Impact

- Supabase `message_attachments` 스키마와 이미지 메시지 생성·조회 RPC가 변경된다.
- Flutter 메시지 모델, 이미지 업로드 전처리, repository 및 이미지 위젯이 영향을 받는다.
- Web에 Cache Storage 또는 IndexedDB 기반의 제한된 영속 이미지 캐시 계층이 추가된다.
- 로그아웃 흐름이 현재 사용자의 비공개 이미지 캐시 정리를 호출한다.
- 기존 첨부 데이터와 클라이언트의 하위 호환성을 유지하는 migration 및 테스트가 필요하다.
